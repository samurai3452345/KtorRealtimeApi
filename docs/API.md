# REST API и WebSocket

Базовый адрес: `http://localhost:8091`. JSON кодируется UTF-8. В REST JWT передаётся заголовком `Authorization: Bearer <accessToken>`. Публичные маршруты не требуют токен. В Swagger UI нажмите **Authorize** и вставьте JWT.

## Учётная запись и права

Регистрация: `POST /api/auth/register` с `{"username":"student_demo","password":"StudentDemoPass123!"}`. Имя — 3–32 латинские буквы, цифры и `_`; приводится к нижнему регистру. Пароль — 10–128 символов. Роль регистрации всегда `user`. Вход: такое же тело на `POST /api/auth/login`.

Оба успешных запроса возвращают `{"accessToken":"...","tokenType":"Bearer","expiresIn":3600,"user":{"id":1,"username":"student_demo","role":"user","createdAt":"2026-10-23T07:00:00Z"}}`. `expiresIn` — секунды, `createdAt` — строка времени в ISO 8601. Идентификаторы — `Long`; конкретные значения в примерах условные.

`GET /api/users/me` возвращает `user`. Администратор читает `GET /api/admin/users?limit=100&offset=0` и меняет роль через `PATCH /api/admin/users/{id}/role`, тело `{"role":"admin"}` или `{"role":"user"}`. Администратор не может снять собственную роль: `403`. Обычный пользователь на административном маршруте получает `403`.

## Сообщения

`POST /api/messages`, тело `{"text":"Привет!"}`, возвращает `201` и сообщение: `{"id":1,"userId":2,"username":"student_demo","text":"Привет!","createdAt":"2026-10-23T07:00:00Z"}`. Текст — 1–2000 символов после нормализации пробелов по краям. Отправка через REST также публикует событие в WebSocket-чате.

`GET /api/messages?limit=50&before=123` возвращает JSON-массив сообщений с идентификаторами меньше `123`, от новых к старым. `before` необязателен. `limit` по умолчанию `50`, допустимо `1..200`. Для следующей страницы передайте ID последнего элемента как `before`.

## Оповещения

Администратор отправляет `POST /api/admin/notifications` с телом `{"title":"Объявление","message":"Начало занятия","userId":2}`. При `"userId":null` оповещение получает каждый существующий пользователь, включая администратора. Заголовок — 1–100 символов; текст — 1–2000. Ответ `201`: `{"delivered":1}` — количество созданных записей, включая получателей, которые сейчас офлайн.

`GET /api/notifications?limit=100` возвращает только собственные оповещения; `limit` от `1` до `200`. Элемент: `{"id":1,"userId":2,"title":"Объявление","message":"Начало занятия","read":false,"createdAt":"2026-10-23T07:00:00Z"}`. `PATCH /api/notifications/{id}/read` помечает собственную запись прочитанной и возвращает её. Чужой или отсутствующий ID даёт `404`.

## WebSocket

Подключитесь к `ws://localhost:8091/ws`. Чат и личные оповещения приходят по одному соединению. Соединение само по себе не авторизует пользователя: в течение **5 секунд** нужно отправить текстовый JSON-кадр:

```json
{"type":"auth","token":"JWT_ИЗ_ОТВЕТА_LOGIN"}
```

JWT не передаётся в query-параметрах, URL или WebSocket-subprotocol. После подтверждения приходит событие `ready`. В чат отправляется `{"type":"message","text":"Привет!"}`; сервер сохраняет сообщение и рассылает событие `message` участникам. Администратор создаёт оповещения через REST, сервер доставляет событие `notification` только нужному пользователю.

Примеры серверных кадров:

```json
{"type":"ready","detail":"Connected"}
{"type":"message","message":{"id":1,"userId":2,"username":"student_demo","text":"Привет!","createdAt":"2026-10-23T07:00:00Z"}}
{"type":"notification","notification":{"id":1,"userId":2,"title":"КТ 4","message":"Начало занятия","read":false,"createdAt":"2026-10-23T07:00:00Z"}}
{"type":"error","detail":"Expected a message command"}
```

Необязательные поля `message`, `notification`, `detail` могут отсутствовать или быть `null`; клиент выбирает нужное поле по `type`.

Серверные типы событий: `ready`, `message`, `notification`, `error`. При ошибке авторизации / истечении токена соединение закрывается; клиенту нужно войти и подключиться заново. При восстановлении соединения историю чата и оповещения загрузите через REST: WebSocket не заменяет постоянное хранилище. Число активных соединений в этой учебной реализации хранится в памяти одного процесса; для нескольких экземпляров нужен общий брокер событий.

Минимальный пример в консоли браузера на странице приложения:

```javascript
const token = prompt('Вставьте accessToken из login');
const socket = new WebSocket('ws://localhost:8091/ws');
socket.addEventListener('open', () => socket.send(JSON.stringify({type: 'auth', token})));
socket.addEventListener('message', event => console.log(JSON.parse(event.data)));
// Выполните после получения ready:
socket.send(JSON.stringify({type: 'message', text: 'Привет из WebSocket!'}));
// Оповещения приходят по этому же соединению с type: 'notification'.
```

Обычный OpenAPI 3.0 описывает HTTP-контракт; поток WebSocket-кадров документируется здесь отдельно. Браузерный интерфейс на `/` позволяет продемонстрировать поток без дополнительного клиента.

## Ошибки и здоровье

REST-ошибки имеют форму `{"error":"описание"}`. Основные статусы: `400` — некорректное тело/параметры; `401` — отсутствующий, неверный или истёкший JWT / неверный пароль; `403` — недостаточно прав; `404` — отсутствующий ресурс; `409` — занятое имя; `500` — внутренняя ошибка без выдачи деталей БД клиенту.

`GET /health/live` возвращает `200` и `{"status":"ok"}`. `GET /health/ready` проверяет соединение с PostgreSQL: `200` при готовности и `503` при недоступной БД. Эти маршруты не требуют JWT; ready используется Docker healthcheck.
