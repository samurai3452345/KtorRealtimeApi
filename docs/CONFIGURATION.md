# Конфигурация и секреты

`.env.example` описывает состав настроек без действующих секретов. `scripts/Init-Env.ps1` / `scripts/init-env.sh` создают `.env` со случайными значениями криптографического генератора. Повторный запуск не заменяет файл. В Bash файл создаётся с ограниченными правами (`umask 077`). В Windows файл наследует права каталога пользователя.

Docker Compose автоматически читает `.env`. При локальном запуске скрипт `Run-Local.ps1` / `run-local.sh` преобразует `POSTGRES_*` в настройки приложения. Сам JVM-процесс читает переменные окружения, а не `.env`.

| Переменная JVM | Значение / требование |
| --- | --- |
| `DATABASE_URL` | По умолчанию `jdbc:postgresql://localhost:55435/ktor_realtime`; в Docker используется имя сервиса `postgres` и порт `5432` |
| `DATABASE_USER` | По умолчанию `realtime_app` |
| `DATABASE_PASSWORD` | Обязательна; локальный скрипт берёт `POSTGRES_PASSWORD` |
| `JWT_SECRET` | Обязателен, не менее 32 символов; генерируется 96 hex-символов |
| `JWT_TTL_SECONDS` | По умолчанию `3600` — один час |
| `ADMIN_USERNAME` | По умолчанию `admin` |
| `ADMIN_PASSWORD` | Обязателен, не менее 10 символов; генерируется 48 hex-символов |
| `PORT` | По умолчанию `8091`; локальный скрипт берёт `APP_PORT` |

Переменные Compose: `POSTGRES_DB=ktor_realtime`, `POSTGRES_USER=realtime_app`, `POSTGRES_PASSWORD`, `APP_PORT=8091`, `PG_PORT=55435`. Не помещайте в значения переводы строк, кавычки или shell-выражения: скрипты используют простой формат `NAME=value`. Для ручного задания секретов удобны случайные hex-строки.

При первой инициализации приложение создаёт администратора из `ADMIN_*`, если такого пользователя ещё нет. Переменные начального администратора не служат механизмом смены пароля существующего пользователя. Изменение пароля PostgreSQL в `.env` также не изменяет пароль уже созданной БД в volume: его нужно изменить в PostgreSQL и затем синхронизировать конфигурацию.

JWT — bearer-секрет: владелец токена получает доступ до истечения срока действия. Не публикуйте токены, `.env`, приватные переменные HTTP Client и дампы БД. Смена `JWT_SECRET` делает ранее выпущенные JWT недействительными; после неё потребуется повторный вход. Роль пользователя проверяется по БД при обращении к защищённым маршрутам, поэтому изменение роли действует без перевыпуска токена.

Пример предназначен для локальной сдачи. Для доступа из сети нужны HTTPS/WSS через обратный прокси, защищённое хранение секретов и резервное копирование. В Docker Compose порты привязаны к localhost; для локальной демонстрации это дополнительной настройки не требует.
