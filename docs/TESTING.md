# Проверка проекта

## Автоматические проверки

Windows: `.\mvnw.cmd -B verify`. Linux/macOS: `bash ./mvnw -B verify`.

Maven компилирует Kotlin и запускает тесты из `src/test`. Итог — `BUILD SUCCESS` или `BUILD FAILURE` в выводе Maven, отчёты — `target/surefire-reports`.

Локальная проверка 23.10.2026: **14 тестов, 0 ошибок, 0 падений, 0 пропусков**, включая реальный PostgreSQL 17. Состав: `ApiTest` — 8, `PostgresStoreTest` — 1, `RealtimeTest` — 4, `SecurityTest` — 1. Исполняемый JAR запущен локально на `8091`, PostgreSQL — на `55435`; `docker compose config --quiet` успешно проверил конфигурацию Compose. Локальный Docker runtime не проверен из-за ошибки установленного Docker Desktop Secrets Engine (`engine.sock`).

CI запускает `verify` на JDK 17 с отдельным сервисом PostgreSQL 17, затем генерирует секреты, собирает и запускает Docker Compose с ожиданием healthy, проверяет `/health/ready`, `/swagger`, `/openapi.yaml` и удаляет контейнеры и volume временного runner. Пароль сервиса интеграционных тестов в workflow действует только в одноразовой CI-среде. Результат CI следует смотреть в GitHub Actions; локальная проверка не означает успешного запуска Docker в CI.

Обычный `verify` выполняет API/WebSocket/безопасность с тестовым хранилищем в памяти. `PostgresStoreTest` пропускается, если не задан `TEST_DATABASE_URL`. Для проверки SQL-ограничений, изоляции пользователей, пагинации и сохранения данных после открытия нового пула запустите БД и выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-Postgres.ps1
```

Скрипт читает локальный `.env`, задаёт `TEST_DATABASE_URL`, `TEST_DATABASE_USER`, `TEST_DATABASE_PASSWORD` и выполняет `verify`, не печатая пароли. Тест создаёт записи с уникальным префиксом и удаляет только их. Схема при этом применяется к выбранной БД; для проверки в другой среде укажите отдельную тестовую БД. На Linux/macOS задайте эти три переменные окружения вручную перед `bash ./mvnw -B verify`.

Проверка конфигурации Docker без запуска контейнеров: сначала создайте `.env`, затем выполните `docker compose config --quiet`. Не публикуйте вывод `docker compose config` без `--quiet`: подставленные значения содержат секреты.

## Ручная проверка

Сценарии для IntelliJ HTTP Client находятся в `requests.http`. Запускайте запросы сверху вниз: регистрация / вход сохраняют пользовательский токен в `client.global`. Для административных запросов создайте игнорируемый файл `http-client.private.env.json`:

```json
{
  "local": {
    "adminUsername": "admin",
    "adminPassword": "СКОПИРУЙТЕ_ИЗ_ЛОКАЛЬНОГО_ENV"
  }
}
```

В HTTP Client выберите окружение `local`. Не вставляйте реальный пароль в отслеживаемый `requests.http`.

| Проверка | Ожидаемый результат |
| --- | --- |
| Регистрация нового корректного имени | `201`, роль `user`, JWT |
| Повторная регистрация этого имени | `409` |
| Слишком короткий пароль | `400` |
| Вход с неверным паролем | `401` |
| `GET /api/users/me` без токена / с испорченным токеном | `401` |
| Доступ user к `/api/admin/users` | `403` |
| Сохранение сообщения и чтение истории | `201`, затем запись в массиве |
| Пустой текст сообщения / `limit=201` | `400` |
| Изменение роли администратором | Новая роль в ответе и в `/api/users/me` |
| Попытка снять собственную роль admin | `403` |
| Оповещение конкретному пользователю | Только его REST-список и WebSocket получают запись |
| Пометка чужого оповещения прочитанным | `404` |
| Два авторизованных WebSocket-чата | Сообщение видно в обоих соединениях |
| WebSocket без кадра auth в течение 5 секунд | Соединение закрывается |
| Перезапуск приложения | Пользователи, сообщения и оповещения сохранены |

## Если не запускается

- **Docker daemon недоступен.** Запустите Docker Desktop, дождитесь его готовности и проверьте `docker info`.
- **Порт занят.** Для Docker измените `APP_PORT` / `PG_PORT` в `.env`, затем повторите `docker compose up -d`. Для локального JVM-процесса остановите контейнер `app`.
- **Нет JDK / неверная версия.** Укажите JDK 17 в `JAVA_HOME`, Project SDK и Maven Runner.
- **Ошибка подключения к PostgreSQL.** Проверьте `docker compose ps` и `docker compose logs --tail 100 postgres`. В Docker адрес БД `postgres:5432`; при запуске из IDEA — `localhost:55435`.
- **Пароль изменён в `.env`, но вход в БД не работает.** PostgreSQL применяет `POSTGRES_PASSWORD` только при создании пустой БД. Синхронизируйте пароль существующей БД; пересоздание volume удаляет данные.
- **JWT перестал действовать.** Войдите снова; сравните настройки `JWT_SECRET` у запущенного приложения. Токен также истекает по `expiresIn`.
- **`409` при повторной регистрации демопользователя.** Выполните следующий запрос входа или выберите другое имя.
- **Ошибка Maven при первом запуске.** Для загрузки зависимостей требуется доступ к Maven Central; proxy и offline-mode настраиваются в Maven/IDEA.
